手写Agent的第一性原理——从零构建ReAct主循环
学操作系统要写迷你OS，学数据库要写迷你数据库。学Agent开发，如果只是用现成框架搭一搭，而不理解内部的运行机制，就很难真正落地。 用Agent好比开车，但要修车甚至造车，就必须从底层原理出发。

ReAct循环是Agent的最小骨架。 2023年Google和普林斯顿提出的ReAct范式，核心思想是让模型在“推理”和“行动”之间交替进行，形成“思考→行动→观察→再思考”的闭环。用最基础的模型API手写一个能够“思考—调用工具—观察结果—继续执行”的最小Agent，整个结构可以压缩成一个while循环：调用模型、判断是否需要工具、执行工具、把结果放回上下文，直到任务完成。

循环终止条件的设计决定了Agent能否收敛。 经典反面案例是AutoGPT——无限循环、无验证、上下文爆炸。合理的终止条件需要多层保护：max_turns限制最大步数防止死循环，任务完成判定基于结构化退出状态而非自然语言判断，预算熔断在token消耗超出阈值时强制终止。agent-lab项目实现了四种结构化退出状态，跑6类任务评测通过率达到100%，合计11步、5次工具调用，其中包含一次失败后被纠正的过程。

异常回注是手写Agent与“调一次API”的根本差异。 工具失败不是崩溃，而是转成观察结果交回模型自我纠正。当除零错误发生时，系统将错误信息作为Observation写回上下文，模型据此调整策略完成修正。这种“错误即消息”的设计使得Agent具备了基本的自我修复能力，也是ReAct循环区别于简单工具调用的核心所在。

上下文预算管理是循环能长期运行的前提。 每轮工具调用都会向上下文追加结果，若不管理，窗口很快被填满。手写Agent需要在循环中嵌入token估算、结构保全的裁剪和压缩收益防线——保留关键对话结构，丢弃冗余的工具返回值，确保核心指令不被裁剪掉。

对于零基础的学习者而言，先手写一个约100行主循环的最小Agent，再逐步扩展工具系统和上下文管理，是在进入生产框架前建立正确心智模型的最有效路径。
